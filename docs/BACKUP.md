# Резервная копия сайта

На боевом сервере все данные сайта (пользователи, объявления, платежи, фото) лежат только в Docker-томах на самом сервере. В Git их нет, поэтому перед выключением или удалением сервера нужно снять копию.

## Как снять копию

На сервере (окно с приглашением `root@...`):

    bash ~/riveg-rent/database/backup.sh

Скрипт делает папку `~/riveg-backups/ДАТА_ВРЕМЯ/` и рядом один архив `ДАТА_ВРЕМЯ.tar`. В конце он печатает готовую команду `scp ...`: её нужно выполнить в окне Git Bash **на своём компьютере**, архив скачается в домашнюю папку.

Что внутри:

- `database.sql.gz` — база данных без справочника городов;
- `files.tar.gz` — загруженные фото и вложения (`public_html/uploads`, `private_uploads`);
- `env.backup` — файл `.env` с паролями и ключами. Никому не отправляйте архив и не кладите его в Git.

Справочник городов (`_cities`, `_countries`, `_regions`, около 3 ГБ) в копию не входит: он загружается заново из `database/seed/cities.sql` на вашем компьютере (см. `docker compose --profile seed run --rm seed-cities`).

Если скрипт завершился ошибкой, он сам удаляет недоделанную копию и пишет об этом. В таком случае сервер выключать нельзя.

## Как восстановить на новом сервере

1. Поставить Docker, склонировать репозиторий в `~/riveg-rent`, положить `env.backup` как `.env` (поправить `SITE_URL`, если адрес изменился).
2. `docker compose up --build -d` — миграции создадут пустые таблицы.
3. Загрузить города (`seed-cities`, нужен `cities.sql`).
4. Загрузить базу: распаковать `database.sql.gz` и подать в `mysql` внутри контейнера `db`.
5. Распаковать `files.tar.gz` в корень проекта внутри контейнера `app` (`tar -xzf` в `/var/www/html`) и выдать права пользователю `www-data`.
6. Переключить DNS на новый IP и выпустить сертификат (`certbot --nginx`).

Проще всего восстанавливать вместе с Claude: пришлите ему, на каком шаге вы находитесь.
